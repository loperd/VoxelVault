# 0.4.2

A player is no longer sent to the sign-in screen every fifteen minutes. When the short-lived access cookie expires, the client asks the gateway to refresh the session once (concurrent requests share that refresh) and repeats the request. Only when the gateway refuses the refresh does the client clear the game's saved state in localStorage (the sound setting stays) and then show the sign-in screen. A failed network request for the refresh does not sign the player out. Opening the page after a pause refreshes the session the same way.

The release procedure (a `release/v<version>` branch merged into master, the tag only on master) is described in docs/guides/releases.md.
